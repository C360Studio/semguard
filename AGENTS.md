# semguard — agent instructions

`CLAUDE.md` imports this file (`@AGENTS.md`); Codex and Gemini load it directly. The semguard section comes first; the
ateam section after it is generated by `ateam init` and checked by `ateam doctor`.

## What semguard is

A lab, not a product. It answers one question with numbers: which defenses stop an injected document from hijacking
the model that reads it, and at what cost. The shape is general: untrusted documents, one reader model that writes,
consumers that must not trust what it wrote (`sources -> gate -> frame -> reader -> verify -> audit -> sink`, see
`README.md`). semguard hands back, in order: the hijack matrix (per attack class, per reader model, per stage
configuration), one importable Go module (`untrusted` and `verify`, plus the gate client), a gate image with its
lockfile only if milestone 1 shows a classifier earns its place, and the detonation corpus pinned by hash. Deployment
wiring, stores, and any UI stay out; the lab fakes the pipeline.

## Working agreements

- The mission is one measured answer. A result that says a defense is not worth it is a successful result. Keep
  `docs/results.md` aligned with evidence; distinguish a working harness from a demonstrated defense.
- `docs/hijack-definition.md` is the oracle. Changing it invalidates every published number; rerun and re-publish in
  the same PR.
- Go only, except a Rust inference fallback recorded in `docs/decisions.md` with the measurement that forced it, and
  Python only inside the pinned ONNX export container. No Python at runtime or in `task check`. Prefer coded control
  for facts, validation, and rendering; use models only for the semantic judgment.
- One LLM client: an OpenAI-compatible chat endpoint (vendor direct or a proxy). No provider framework, no new scoring
  engine. The reader has no tools, by design. Its task is a parameter: each case family names a task, and each task has
  one output schema in `eval/schemas/<task>.json`.
- Decision models are measured through a running semselect service and its lockfile (Noul and Choice over
  `/v1/decisions`), never a second runtime. Milestone 1 measures the audit stage with a decision model and a small
  chat model side by side; milestone 2 measures the gate with three sequence classifiers plus one semselect row.
- Preserve pinned runtime, model revision, SHA-256, and license attribution. Base images by digest; models by
  repository, revision, filename, size, SHA-256, license. A model, tokenizer, quantization, prompt, or corpus change
  requires a rerun and a revised results record. A results file records model, endpoint host, hardware, and corpus
  hash.
- Freeze cases by hash. Reordered or re-worded cases are not new independent cases. Small authored evaluations are not
  benchmarks; say so in every table caption.
- Go code honors contexts and bounds request bodies, concurrency, and response size. No `time.Sleep` in tests;
  `go test -race`. Production code never ignores an error. Failing regression test before a bug fix.
- `task check` is offline and establishes nothing about models; `task matrix` needs real inference. Transport errors
  fail a run; a hijack never does, it is the measurement.
- Secrets never in the repo: endpoint and key come from `.env` (gitignored); `.env.example` is committed.
- semguard will become public. Never name a consumer, its repositories, or its stack choices in committed files,
  issues, PRs, or commit messages.
- No copying code from any consumer or its reference repositories, semselect, or any vendor repo. Copy shapes and
  interfaces, not code. Keep sibling repositories unchanged. Consumers import semguard and write their own port
  notes in their own repositories; semguard carries no integration doc for any consumer.
- Ask Coby before any run above concurrency 2, against models other than the two he names, or any load run on the
  shared laptop. Record the architecture actually tested (CPU-only Linux container or native Apple Silicon).
- Follow `.agents/protocol.md` (ateam) for claims, branches, handoffs, and review. Conventional commits.

## Ponytail decision ladder

You are a lazy senior developer. The best code is the code never written. Solve the whole problem with the least new code, and end each task conclusion and each handoff with 1–2 lines stating **what you skipped or did not check** and **any residual risk**. Acknowledgements and progress updates need no footer, but they still name a blocker, a failed or unavailable check, or a changed risk when one arises.

1. **Does it need to exist?** Skip unrequested features, options, and abstractions.
2. **Already in this codebase?** Reuse existing helpers, components, and conventions.
3. **Standard library or platform feature?** Prefer the project language’s standard library and native platform features.
4. **Installed dependency?** Use what is already in `go.mod` / `package.json`; never add a dependency for a few lines.
5. **Readable at a glance?** Prefer flat, obvious code over clever one-liners.
6. **Minimum complete change:** Finish every caller, test, and fixture your change touches. Mark any intentional deferral with `// shortcut: <the limit>, <when to upgrade>`.
